# Daylo Website 1.0

Готовый бесплатный статический сайт Daylo для GitHub Pages. **Нет установщика в ZIP**: это сайт, и кнопка загрузки не должна вести на выдуманный EXE.

## Публикация — инструкция

1. Создай бесплатный аккаунт на https://github.com (если нет).
2. Нажми **New repository**, назови его `daylo-site`, выбери **Public**, создай репозиторий.
3. В репозитории нажми **Add file → Upload files** и загрузи содержимое этой папки: `index.html`, `style.css`, `script.js`, `config.js`, `favicon.svg`, `README.md` (именно файлы в корень, а не папку целиком). Нажми Commit changes.
4. Открой **Settings → Pages**, выбери **Deploy from a branch**, **main**, **/(root)** → Save.
5. Адрес будет вида `https://ТВОЙ-ЛОГИН.github.io/daylo-site/`. Публикация не мгновенная.
6. Для кнопки «Последняя версия» подготовь установщик через сборку Daylo на Windows, затем создай GitHub Release в репозитории `daylo-site` (либо отдельном репозитории для приложения). Загрузи файл `Daylo_Setup_7.0.4.exe` или другой проверенный установщик. Назови релиз `v7.0.4`, опубликуй его **не как prerelease**.
7. В `config.js` замени `window.DAYLO_REPO = '';` на `window.DAYLO_REPO = 'ТВОЙ-ЛОГИН/daylo-site';` (или иной репозиторий релизов) и сохрани через коммит. Тогда кнопка автоматически будет вести на `releases/latest`.

## Как выпускать следующую версию

Собери и проверь новый установщик, создай новый Release, прикрепи EXE и опубликуй. Если используется тот же репозиторий, кнопка сайта будет автоматически вести на последний опубликованный релиз.

## Безопасность

Не добавляй в публичный репозиторий личную базу `%LOCALAPPDATA%\DailyWidget`, резервные копии, токены GitHub или пароли. Сайт можно публиковать отдельно от исходного кода самого приложения.
